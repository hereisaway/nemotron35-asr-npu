## Stream-sync test guard (`test_model_runner.py`)

The test built `torch.device("npu")` unconditionally. On a host where
`torch_npu` has not registered the device type that raises before the
`monkeypatch`, so the test errors instead of skipping:

```
>>> torch.device("npu")
RuntimeError: Expected one of cpu, cuda, ipu, xpu, mkldnn, ...
```

It now uses this file's existing NPU marker idiom:

```python
NPU_REQUIRED = pytest.mark.skipif(
    not hasattr(torch, "npu") or not torch.npu.is_available(), reason="NPU required"
)
NPU_ACCELERATOR_MARKS = [pytest.mark.accelerator, NPU_REQUIRED]
```

with `@pytest.mark.accelerator` + `@NPU_REQUIRED` on the test. The duplicated
skipif condition that was already inline in `NPU_ACCELERATOR_MARKS` was folded
into the shared constant at the same time.

**Do not use `tests/unit_test/fixtures/accelerator.py::require_device_streams()`
here.** That helper gates on `supports_device_streams()`, which deliberately
excludes `npu` ("Ascend NPU has them but waits for its own measurements"), while
#4381 exists to move these call sites onto `has_device_streams()`, which does
include `npu`. Measured on the 910B4 pod, the helper produced:

```
test_streaming_batch_synchronizes_the_stream_device SKIPPED (npu has no device streams)
```

so the test would have passed review and then never run on the target hardware.
With the marker guard it reports `PASSED` on 910B4 and skips only where
`torch_npu` is not available.

### Reproducing the unit tests without the full pod environment

The pod's `/opt/venv` already has torch/torch_npu, but not the sglang-omni test
dependencies. An isolated target directory is enough and avoids touching the
shared environment:

```bash
pip install --target /tmp/deps transformers==5.19.0 pytest numpy==1.26.4 \
    msgspec msgpack pydantic pyyaml pyzmq pybase64 xxhash "typing-extensions>=4.13" \
    librosa soxr
pip install --no-deps --target /tmp/deps sglang==0.5.23
pip install --no-deps --target /tmp/deps --index-url https://download.pytorch.org/whl/cpu \
    torchvision==0.24.0 torchaudio==2.9.0
PYTHONPATH=/tmp/deps:. python3 -m pytest tests/unit_test/nemotron3_5_asr
```

Two traps: `pip install sglang` pulls a different torch into the target
directory and shadows the pod's build (install it `--no-deps`), and
`torchvision` / `torchaudio` must be the `+cpu` wheels matching torch 2.9.0 or
the import fails in `torchvision::nms` / `_torchaudio.so`.
